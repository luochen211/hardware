# ESP32 WS2812 实验过程复盘

**分类：硬件 / ESP32 / 实验复盘**  
**项目：老师提供的 `exp1_blink`；公开仓库源码中的学生字段已替换为通用占位符。**

## 实验实际完成情况

工作副本已用 ESP-IDF 6.1 编译并烧录到 ESP32-D0WD-V3。串口监视器实际读到学生信息及循环状态：`红色`、`绿色`、`蓝色`、`白色`、`熄灭`。这证明固件运行并持续输出这些日志；单凭日志不能证明每颗 WS2812 的实际颜色显示均正确。

这份固件是 WS2812 灯实验，不是智能农业采集程序。当前 `main.c` 没有 ADC 配置、土壤湿度采样或湿度串口输出，所以看不到湿度是预期现象，不能据此断定传感器或主板坏了。

## 过程中遇到的问题

### 1. 把“USB 串口已连接”当作“网页能读到传感器”

- **现象：** 页面一直显示等待传感器，期待湿度和灯状态同步出现。
- **原因：** 浏览器只能读取串口实际收到的字节；固件必须实现传感器采集并按页面可识别的格式发送数据。当前烧录的只是 WS2812 演示固件。
- **下次做法：** 先核对当前烧录固件的功能和串口协议，再判断传感器、固件或页面哪一层缺数据。

### 2. ESP-IDF 激活脚本指向旧安装目录

- **现象：** `activate_idf_v6.1.sh` 报找不到 `~/.espressif/v6.1/esp-idf/tools/cmake/version.cmake`；之后组件管理器又因版本字符串为空报错。
- **原因：** 实际 IDF 位于 `~/.espressif/eim-install/v6.1/esp-idf`，但激活脚本仍设置旧 `IDF_PATH`，且 `ESP_IDF_VERSION` / `IDF_VERSION` 没有有效值。
- **修正：** 直接设正确的 `IDF_PATH`、`IDF_TOOLS_PATH`、Python venv 和版本变量，再用该 venv 的 Python 运行 `idf.py`。仓库 README 已记录可复用命令。

### 3. 同一串口同时开了两个监视器

- **现象：** `idf.py monitor` 显示端口存在，但报 `Could not exclusively lock port` / `Resource temporarily unavailable`。
- **原因：** 之前启动的监视器仍独占 `/dev/cu.usbserial-1340`。
- **修正：** 关闭旧监视器（`Ctrl+]`）后再开一个。一个串口同一时刻只由一个程序读取。

### 4. 查看了错误的终端面板

- **现象：** Codex 里显示 `ppt-ops-full` 空终端，看不到板子的日志。
- **原因：** 那个面板是普通 shell，不是串口监视器会话；打开会话的操作只进入队列，没有显示到该面板。
- **下次做法：** 在明确的终端窗口运行 `idf.py monitor`，确认标题、工作目录和端口，再判断是否有输出。命令行有输出不代表其他终端面板也会自动显示。

### 5. 引脚资料互相矛盾，注释不能当接线结论

- **现象：** 资料中出现 GPIO14、GPIO21、GPIO23 等不同说法。
- **原因：** 教师说明、源码头部注释和实际宏配置没有完全统一；当前源码宏值为 GPIO14。
- **下次做法：** 以板卡原理图/接线定义和实际测得结果为准，记录引脚后再烧录，避免只凭文字注释判断。

## 后续智能农业实验需要的工作

1. 确认土壤湿度传感器型号、供电方式、模拟输出范围及接入的 ESP32 ADC 引脚。
2. 在固件中新增 ADC 读取和干湿两点校准，将原始读数换算成相对湿度百分比。
3. 在串口输出固定、明确的数据格式，再让网页解析；若网页通过 Web Serial 读取，确保浏览器已授权正确端口且没有其他进程占用。
4. 分别验证原始 ADC 值、干土/湿土变化和网页更新。未接传感器或未加入采样代码时，不应期待湿度读数。

## 证据边界

- **已验证：** 工程编译成功；固件已烧录；串口日志包含学号姓名及五种颜色状态；监视器独占冲突确实发生过。
- **未据此验证：** 土壤湿度传感器是否损坏、实际模拟值、网页端数据解析、所有灯珠的实物颜色。当前固件没有湿度采集路径。
