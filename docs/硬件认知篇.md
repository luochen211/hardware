## 一、一套联网硬件怎样工作

![联网硬件的感知层、网络层和应用层，以及数据上报与控制命令的双向流动](images/iot-three-layer-architecture.png)

以“手机显示土壤湿度，并能控制一个设备”为例，信息要经过一条完整链路：

```text
土壤状态 → 传感器信号 → ESP32 读取与处理 → Wi-Fi / 蓝牙 → 手机或网页
                                                      ↓
手机发出命令 → 通信链路 → ESP32 判断 → 驱动电路 → 灯、继电器或电机
```

传感器把物理状态变成电信号。ESP32 固件通过 ADC、GPIO、I2C 等接口读取，再把选择上报的数据送往应用。应用能显示收到的信息，也能发回控制命令；真正让灯或电机动作的仍是设备端的电路与程序。

这里有一个容易混淆的边界：**手机看见一个湿度值，只能证明它收到了这个值**。这还不能证明传感器供电正确、接线正确，也不能证明读数经过校准。要确认真实状态，需要结合原理图、串口日志、原始采样值和实物测量。[实验 3B](../experiments/exp3b_farm/README.md)练习土壤、光照和雨滴的 ADC 采集；[实验 8B](../experiments/exp8b_rainmaker/README.md)则尝试把真实 DHT11 和烟雾数据送到 RainMaker。

## 二、ESP32、开发板与芯片是什么关系

```text
芯片（ESP32 MCU）→ 加上供电、USB 转串口和引脚等 → 开发板
开发板 + 传感器 + 驱动电路 + 固件 + 外壳等 → 设备或产品
```

在这个例子里，负责读取和处理信号的 ESP32 是一类把处理器、存储和常用外设集成在一起的单片机。芯片是集成在半导体材料上的电路；开发板让我们更容易给芯片供电、烧录程序和连接外设。这个仓库的实验是在**使用现成芯片开发固件与系统**，并没有设计或制造 ESP32 芯片。

![从设计芯片、形成版图，到晶圆制造和封装的过程](images/chip-design-to-fabrication.png)

若要设计一颗新芯片，通常要经过需求与规格、电路或逻辑设计、仿真验证、版图设计与检查，再把签核后的设计数据交给晶圆厂制造。交付制造数据的关键节点叫**流片**。流片后还要经过晶圆制造、测试、切割、封装和成品测试；流片本身不代表芯片已经成功。

![流片前的功能、版图和实现验证，以及流片后发现问题的返工代价](images/why-tapeout-is-hard.png)

芯片设计困难的原因之一，是制造前必须尽量找出功能、版图和性能问题。真实硅片回来后才发现错误，往往要修改设计并重新制造。开发板实验也要验证，但成本和返工周期与重新流片不是同一量级。更完整的流程与术语见[芯片从设计到流片](芯片从设计到流片.md)。

## 三、为什么实验要逐层推进

一开始就把传感器、网络、手机界面和执行器接在一起，出了问题很难知道是哪一层。仓库的八个阶段让每次新增一个能力，都有可以观察的结果：

| 能力 | 对应阶段 | 首先确认什么 |
| --- | --- | --- |
| 输出与本地交互 | 1–2：彩灯、按键 | 固件运行、引脚响应、串口日志 |
| 感知与动作 | 3–4：传感器、执行器 | 原始读数随环境变化；输出动作符合控制信号 |
| 连接与消息 | 5–7：Wi-Fi、蓝牙、MQTT | 配网、断线、上报和命令是否按预期工作 |
| 系统集成 | 8：MQTT 或 RainMaker | 数据、控制与界面能否连成一条完整链路 |

这条路线是**学习顺序**，不是所有工程都已通过设备验收。第 5、7、8A 阶段的温湿度数据是模拟值，适合先练通信流程；它们不能证明真实传感器采集已完成。构建产物也只说明曾产生固件文件，不能替代接线、烧录和现场观察。具体工程与选择分支见[仓库总览](../README.md#第一部分实操)。

## 四、从原型走向产品要补什么

如果要把这个盆土监测演示交给别人长期使用，就不能只看手机上是否出现过一次读数。一个硬件原型走向可重复交付，通常还要检查供电与接口、传感器校准、环境适应性、异常停机、断线恢复、测试工装、认证、制造、库存和售后。需要补哪些环节，取决于设备用途与交付规模。

![硬件与软件在入行条件、经验积累和职业挑战上的对比](images/hardware-vs-software-careers.png)

硬件工作往往要等待样机、测量和生产反馈；软件原型通常更容易在电脑上构建和迭代。这会影响入门方式与经验积累，但不能推导出“硬件职业一定稳定”或“软件经验不值钱”。跨电路、固件与现场排障的经验有价值，复杂软件系统的设计与维护经验也同样会积累。更细的讨论见[硬件与软件：入行门槛和经验积累](硬件与软件职业路径对比.md)。

![硬件、软件与 AI 服务在原型、规模部署和持续运营阶段的投入结构](images/investment-hardware-software-ai.png)

硬件的器件、样机、测试和制造投入通常更早出现，而且每多生产一台仍有物料、组装和测试成本。软件的复制成本通常较低，但研发、云服务、安全和维护持续产生费用。AI 演示可以调用托管模型快速起步，规模运行仍要承担推理、算力、网络与能源成本。这里比较的是**投入发生的阶段和方式**，并不是给三类项目排一个固定的贵贱顺序。详见[硬件、软件与 AI：投入发生在哪里](硬件软件与AI时代的投入结构.md)。
